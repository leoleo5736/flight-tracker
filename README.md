# 機票價格每日追蹤

追蹤 **2026/10/08 台北 → 西雅圖**、**2026/10/18 西雅圖 → 台北** 的長榮直飛機票價格。
每天早上 9 點自動抓一次，累積成價格紀錄，讓你判斷「現在這個價格算高還是算低」。

---

## 這東西實際上在做什麼

每天早上九點，GitHub 的免費伺服器會幫你做這三件事：

1. 去 Google Flights 查當天的長榮直飛**來回票**價（去程 BR24、BR26 兩班，每班標的都是來回總價）
2. 把 2 筆價格寫進 `prices.csv`
3. 如果你有設定 Google 試算表，順便也寫一份進去

你什麼都不用開、不用按。資料自己累積。

---

## 步驟一：把檔案放上 GitHub

### 1-1 建立一個新的 repo

到 <https://github.com/new>：

- **Repository name** 填 `flight-tracker`（或任何你喜歡的名字）
- 選 **Private**（私人的就好，不需要公開）
- **不要**勾 "Add a README file"
- 按 **Create repository**

### 1-2 上傳檔案

建好之後畫面上會有一行 **uploading an existing file** 的連結，點它。

然後把這四個東西拖進去：

```
scrape.py
requirements.txt
README.md
.github/          ← 整個資料夾一起拖
```

> **⚠️ 這裡最容易出錯**
> `.github` 這個資料夾在 Windows 檔案總管裡可能看不到（因為開頭是點）。
> 如果看不到，在檔案總管上方點 **檢視 → 顯示 → 隱藏的項目**，打勾就會出現。
>
> 一定要**整個資料夾拖進去**，不能只拖裡面的 `daily.yml`，
> 不然 GitHub 找不到排程設定，就不會自動執行。

拖完之後，畫面下方按綠色的 **Commit changes**。

---

## 步驟二：手動測試第一次執行

### 2-1 打開 Actions

在你的 repo 上方那排選單點 **Actions**。

第一次進去會看到一個綠色按鈕寫 **I understand my workflows, go ahead and enable them**，按它。

### 2-2 手動跑一次

左邊會看到 **每日抓機票價格**，點它。

右邊會出現一行灰字 **This workflow has a workflow_dispatch event trigger**，
右邊有個 **Run workflow** 按鈕，點下去，再點一次綠色的 **Run workflow** 確認。

### 2-3 看結果

等大約 1～2 分鐘，重新整理頁面，會看到一筆執行紀錄。
點進去，往下捲，就會看到當天的價格摘要，長這樣：

```
2026-08-24 10:32 最低來回總價 NT$26,257

- 去程 BR24 (23:00 起飛) 來回總價 NT$26,257
- 去程 BR26 (23:40 起飛) 來回總價 NT$26,257
```

**看到這個畫面就代表整套系統活了。** 之後每天早上九點會自己跑一次，你不用管它。

### 2-4 資料存在哪

回到 repo 首頁，會多出一個 `prices.csv`。點進去可以直接在網頁上看，
也可以按右上角下載回來用 Excel 開（中文欄位名稱會正常顯示）。

## 步驟三：（選擇性）同時寫進 Google 試算表

**這一步可以先跳過。** 不做的話系統照樣運作，資料存在 `prices.csv` 裡。

會想做這步，是因為你另外兩個旅遊網站已經是「Google 試算表當資料庫」的架構，
之後要畫價格走勢圖、或跟既有的「機票」分頁整合，用試算表會順很多。

### 3-1 在試算表裡貼上接收程式

打開你的 Google 試算表 → 上方選單 **擴充功能 → Apps Script**。

把編輯器裡原本的內容全部刪掉，貼上 `apps-script/Code.gs` 的全部內容。

貼完之後，**改第 15 行**：

```javascript
var SECRET_TOKEN = '請改成你自己的密碼abc123';
```

把引號裡面改成你自己想的一串英文數字，例如 `myFlight2026xyz`。
**記下來，等一下要用。**

按上方的儲存圖示（💾）。

### 3-2 部署成網頁應用程式

右上角點 **部署 → 新增部署作業**。

- 左邊齒輪圖示 → 選 **網頁應用程式**
- **執行身分**：選「我」
- **具有存取權的使用者**：選 **「所有人」**（很重要，不然 GitHub 送不進來）
- 按 **部署**

第一次會跳出授權畫面，一路按 **允許**。
（中間可能出現「Google 尚未驗證這個應用程式」，點 **進階 → 前往（不安全）**，
這是你自己寫的程式，安全。）

最後會給你一串網址，長得像：

```
https://script.google.com/macros/s/AKfyc................/exec
```

**把這串網址複製起來。**

### 3-3 告訴 GitHub 這兩個秘密

回到 GitHub repo → **Settings** → 左邊選單找 **Secrets and variables → Actions**。

按 **New repository secret**，新增兩個：

| Name | Secret（值） |
|---|---|
| `SHEET_WEBAPP_URL` | 剛剛複製的那串 `.../exec` 網址 |
| `SHEET_TOKEN` | 你在 3-1 設的那組密碼 |

設好之後，回 Actions 再手動跑一次。這次執行紀錄裡會看到
`試算表回應: {"ok":true,"added":2}`，表示成功寫進去了。

## 為什麼紀錄裡只有去程航班

Google Flights 查來回票的時候，列出來的是「去程有哪幾班」，
每一班旁邊標的價格，就是「選這班去程的**來回總價**」。
回程要選哪一班是下一步才決定的，Google 不會先給你。

所以 `prices.csv` 每天會有 2 行（BR24、BR26 各一行），
每一行的價格都已經是**整趟來回**的錢，不是單程。

去程航班號程式裡已經對好了：

| 起飛時間 | 航班 |
|---|---|
| 23:00 | BR24 |
| 23:40 | BR26 |

回程（BR23 / BR25）不需要標，因為價格不掛在回程上。

## 步驟四：用網頁看價格走勢

`index.html` 是一頁式的價格看板，會自動讀同資料夾的 `prices.csv`，畫出走勢圖，
並且告訴你「今天這個價，在看過的價格裡算高還算低」。

### 4-1 先把 index.html 上傳

1. 到你的 repo 首頁
2. **Add file** → **Upload files**
3. 把 `index.html` 拖進去
4. 下面按 **Commit changes**

上傳完，repo 首頁應該同時看得到 `index.html` 和 `prices.csv`。

### 4-2 選一條路：手機上看，還是只在電腦上看

**這一步要做個選擇，因為兩種做法差很多。**

| | 做法 A：開 GitHub Pages | 做法 B：不開，直接開檔案 |
|---|---|---|
| 手機能看嗎 | 可以，一個網址到處看 | 不行，只能在電腦上 |
| 要做什麼 | repo 要改成 Public（公開） | 什麼都不用做 |
| 誰看得到 | 有網址的人都看得到 | 只有你自己 |

**「改成 Public 會不會外洩什麼？」**
帳號密碼類的東西不會 —— 那些都放在 GitHub 的 Secrets 裡，不在檔案裡面。
真正會被看到的是**你的旅行日期和航班**（10/08 出發、10/18 回來、長榮直飛）。
如果你不介意這個被陌生人看到，做法 A 比較方便；介意的話就用做法 B。

---

### 做法 A：開 GitHub Pages（手機也能看）

**第一步，把 repo 改成公開**

1. repo 首頁 → 上排的 **Settings**
2. 一路捲到最下面，紅色的 **Danger Zone**
3. 找到 **Change repository visibility** → 按 **Change visibility**
4. 選 **Make public** → 照畫面指示輸入 repo 名稱確認

**第二步，開啟 Pages**

1. 還是在 **Settings**，左邊選單找 **Pages**
2. **Source** 選 **Deploy from a branch**
3. 下面兩個下拉選單：左邊選 **main**，右邊選 **/ (root)**
4. 按 **Save**

**第三步，等一到兩分鐘**

重新整理這個 Pages 頁面，上方會出現一行網址，長這樣：

```
https://你的帳號.github.io/flight-tracker/
```

點進去就是價格看板了。這個網址存到手機書籤，以後隨時打開都是最新的
（因為每天九點程式跑完會把新價格存回 repo，網頁讀的就是那份）。

---

### 做法 B：不開 Pages，在電腦上看

在你電腦上建一個資料夾，放兩個檔案進去：

- `index.html`（從 repo 下載，或用你電腦上本來就有的那份）
- `prices.csv`（到 repo 點 `prices.csv` → 右上角 **Download raw file**）

然後**用滑鼠直接雙擊 `index.html`**，瀏覽器就會打開看板。

缺點是：想看最新價格，得重新下載一次 `prices.csv` 蓋掉舊的。
建議一週做一次就好，不用每天。

---

### 網頁上會看到什麼

**最上面那張色卡** —— 這就是重點。它會說：

- 灰紫色「資料還在累積中」：紀錄不到 3 天，還沒辦法判斷（**現在就是這個狀態**，正常）
- 綠色「目前最低 / 偏低」：這價格在看過的裡面算便宜
- 黃色「中間」：常見價位
- 紅色「偏高」：今天不是好時機

**中間的走勢圖** —— 兩條線是「去程搭 BR24」和「去程搭 BR26」，
灰色虛線是你設定的便宜門檻 NT$24,500，線在虛線以下就是達標了。

這裡要看清楚：**線上的數字是整趟來回的價格，不是去程那一段的價格。**
查的是來回票，一張票含去程（BR24 或 BR26）和回程（BR23 或 BR25）。
Google 回傳的資料只帶去程班次，回程班次沒附進來，所以只能用去程來分兩條線。
「去程搭 BR24 = NT$26,257」的意思是「去程搭 BR24、回程搭當天長榮班機，
整趟一個人 NT$26,257」，回程是含在裡面的。

**下面的表格** —— 最近 20 筆紀錄，低於門檻的價格會標成綠色。

**上面兩個切換鈕** —— 「依去程班次」是預設，看 BR24 和 BR26 的價差；
「早上 vs 晚上」把同一天的兩次抓取放在同一格比較，看日內有沒有波動。
如果兩條線完全重疊，圖上方會直接寫「早上和晚上的價格完全一樣」，不用自己看。

**最上面偶爾出現的橘色警告** —— 代表超過 26 小時沒有新資料進來，
通常是抓取程式失敗了。點進 GitHub 的 Actions 看看是不是紅色叉叉。

## 想改便宜門檻的話

改 **`config.json`** 這一個檔案就好：

```json
"便宜門檻": 24700,
```

`scrape.py` 和 `index.html` 都會讀這個檔案，所以改一次兩邊同步，
不會發生「網頁畫的虛線跟程式判斷的標準不一樣」這種事。

改法：repo 首頁點 `config.json` → 右上角鉛筆圖示 → 改數字 → **Commit changes**。

裡面另外兩個設定：`出發日` 影響網頁的倒數天數，
`資料過期小時` 是超過幾小時沒更新就跳橘色警告（預設 26，因為一天抓兩次，
正常間隔最長是 14 小時，26 小時代表至少漏掉兩次）。

> 萬一 `config.json` 不見了或格式打錯，程式和網頁都會自動退回用 24700，不會整個掛掉。

## 想改設定的話

`scrape.py` 最上面有一段 `SETTINGS`，只有那段需要改：

| 要改什麼 | 改哪一行 |
|---|---|
| 出發／回程日期 | `OUTBOUND_DATE` / `RETURN_DATE` |
| 幾個人 | `ADULTS`（注意：抓到的價格是**每人**價，不是總價） |
| 便宜的標準 | 改 **`config.json`** 的「便宜門檻」，不要改 scrape.py |
| 每天幾點跑 | `.github/workflows/daily.yml` 裡的 `cron` |

**現在的設定是一天抓兩次：台北早上 9 點和晚上 11 點。**

`cron: "0 1,15 * * *"` 是 UTC 時間 01:00 和 15:00，換算台北是 09:00 和 23:00。
想改時間就把數字改掉（台北時間減 8 小時就是 UTC）。只想一天一次就寫 `"0 1 * * *"`。

**為什麼挑這兩個時間？** 機票價格不是即時變動，是透過一個叫 ATPCO 的中央系統分批發送，
國際線一天大約五次。網路上流傳批次時間是美東 10:00、12:00、20:00，
換算後台北 09:00 剛好在美東晚間批次之後，台北 23:00 在美東上午批次之後。

要說清楚的是：**那組時間沒有官方文件佐證**，只在旅遊論壇流傳。
所以這個安排比亂挑好一點，但不保證抓得到價格變動。跑一兩週看資料才知道有沒有用。

## 幾個要知道的限制

**這裡抓的是「來回票總價」，不是兩張單程票相加。** 兩張單程票加起來會貴很多（實測差了 7 千多），
所以程式是直接查來回票。抓到的數字就是「這趟來回一個人要付多少」。

**跟 Google Flights 首頁的數字可能對不上。** Google 首頁顯示的最低價通常是某家旅行社
（例如 ezTravel）的價格，我們抓到的比較接近長榮官網自己賣的價格。兩個都是真的，只是賣家不同。

**兩週的資料回答不了「星期幾買最便宜」。** 那需要好幾個月、跨很多個星期循環才看得出來。
兩週的資料能回答的是另一個問題：**「今天這個價，在我看過的價格裡算高還是算低」**。

這才是這套東西真正的用途 —— 不是「找出最佳購買時機」，
而是「幫我判斷現在這個價格合不合理」。前者兩週辦不到，後者兩週綽綽有餘。

**離出發只剩 6 週了。** 長程線通常在出發前三週開始漲，
所以這套系統的角色比較像是幫你確認「現在買不虧」，而不是等一個大跌。

## 出問題的時候

**Actions 顯示紅色叉叉**
點進去看錯誤訊息。最常見的是 Google 暫時擋了一次，程式本身會自動重試 3 次，
如果還是失敗，隔天九點會再跑一次，不用手動處理。

**連續好幾天都失敗**
可能是 Google Flights 改版了。跟我說，我看一下要改哪裡。

**`prices.csv` 沒有出現**
檢查 `.github` 資料夾有沒有真的上傳成功（在 repo 首頁應該看得到）。
這是最常見的問題。
